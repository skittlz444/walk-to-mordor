## 1. Admin Encounter API

- [ ] 1.1 Create `src/encounter-admin-handlers.ts` with `handleAdminEncountersList`, `handleAdminEncounterCreate`, `handleAdminEncounterGet`, `handleAdminEncounterUpdate`, `handleAdminEncounterEnable`, `handleAdminEncounterDisable`. Each handler validates admin session, performs the requested DB operation on `personal_encounter_definitions`, manages the linked badge definition in `achievement_definitions` (auto-create on save from inline fields, update on edit), logs to `admin_audit_log` on mutation, and returns JSON responses. Uses the existing `logAdminAction` exported from `src/admin-handlers.ts`.
- [ ] 1.2 Implement validation for encounter definition fields: slug (required, max 80, kebab-case unique), name (required, max 120), description (required, max 2000), image_slug (required, max 120), badge_slug (required, max 120), duration_days (required, integer 1-30), target_stretch_multiplier (required, number 1.0-5.0), target_min_distance (required, number > 0, < target_max), target_max_distance (required, number > target_min), is_repeatable (boolean, default true), enabled (boolean, default false on create). Validate `badge_slug` against `achievement_definitions` via lookup — if no match but inline badge fields (badge_name, badge_description, badge_image_slug) are provided, auto-create the achievement definition row. Return `{ error: "validation", fields: { ... } }` on failure.
- [ ] 1.3 Implement disable-with-confirmation: `PUT /api/admin/encounters/:id/disable` without a body checks for active occurrences. If active occurrences exist, returns `{ activeOccurrences: N, requiresConfirmation: true }` (400 status). The client must re-send with `{ cancelActive: true }` to fail all active occurrences, or `{ cancelActive: false }` to disable future rolls only. Audit log records the count of cancelled occurrences when `cancelActive: true`.
- [ ] 1.4 Audit log mutations: insert rows into `admin_audit_log` using `logAdminAction` with `adminUserId`, `action` (create_encounter, update_encounter, enable_encounter, disable_encounter, cancel_active_occurrences), `targetType` = 'personal_encounter', `targetId`, and `details` as JSON with changed fields and active occurrence counts.
- [ ] 1.5 Wire admin encounter routes into `src/index.ts` under the existing `if (url.pathname.startsWith("/api/admin/"))` block: `GET/POST /api/admin/encounters`, `GET/PUT /api/admin/encounters/:id`, `PUT /api/admin/encounters/:id/enable`, `PUT /api/admin/encounters/:id/disable`. Add `matchRoute` patterns to `getAllowedMethods`.
- [ ] 1.6 Add Jest coverage for: admin CRUD operations, badge auto-create on save, badge update on edit, field validation (each rule), non-admin rejection (403), slug uniqueness enforcement, disable with/without active occurrences, cancel vs keep-active confirmation flow, and audit log entries for each mutation type.
