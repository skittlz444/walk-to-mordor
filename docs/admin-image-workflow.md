# Admin Image Workflow

*Last updated: 2026-03-17*

## Key Decision

Images are **repository-backed static assets**, not user-uploaded. No R2, no file uploads. All images are committed to git, optimized at build time, and served via the Cloudflare Workers Assets binding (`env.ASSETS.fetch()`).

## Pipeline Summary

1. Place source image in `raw_assets/` → run `npm run optimize:images`
2. Outputs: `public/img/highres/<slug>.webp`, `public/img/thumbs/<slug>-thumb.webp`, `public/img/image-manifest.json`
3. Commit generated files → deploy → assign `image_id` slug to goal via admin UI

Pipeline script → `scripts/optimize-images.js`

## Rules & Constraints

- **Slug format**: lowercase letters, numbers, hyphens only — regex `/^[a-z0-9]+(-[a-z0-9]+)*$/`
- The filename (minus extension) in `raw_assets/` becomes the `image_id` stored in the goals table
- Thumbnails use `-thumb` suffix: `<slug>-thumb.webp`
- High-res specs: 2048px max, quality 90. Thumbnails: 256px, <20KB target.
- The manifest is fetched at runtime via Assets binding, not filesystem reads — Workers cannot do filesystem I/O at runtime
- Saving a goal with a non-existent `image_id` is allowed (non-blocking validation)

## Image Manifest

`public/img/image-manifest.json` — build-time generated list of all available image slugs.

- Regenerated by: `npm run build:manifest`, `npm run build`, `npm run optimize:images`
- Used by admin UI to browse images, detect orphaned/missing images

## Admin API

| Endpoint | Purpose |
|---|---|
| `GET /api/admin/images` | Cross-referenced inventory: deployed images, orphaned slugs, goals with missing images |
| `PUT /api/admin/goals/:id` | Update goal fields including `image_id` |

Both require admin bearer token (401/403 on failure).
